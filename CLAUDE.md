# Fountain Studio — правила работы над проектом

Этот файл Claude Code читает сам в начале каждой сессии. Здесь — что это за
проект, как его запускать, что обязательно проверять перед сдачей и по каким
правилам мы пишем код. Читается и человеком: новому разработчику начинать
отсюда.

## Что это

Программа управления светомузыкальными фонтанами: DMX512 через Art-Net / sACN /
USB-DMX, таймлайн под музыку, секвенсоры, расписание, 3D-визуализация струй и
света, уведомления в Telegram. Заменяет на объектах старую программу FontanPlay.

Заказчик и главный пользователь — практикующий фонтанщик: он обслуживает
реальные объекты и даёт замеренные с натуры величины (высота струй, время хода
клапана, снос ветром). Калибровать надо по ним, а не по «красиво выглядит».

## Устройство репозитория

npm workspaces, TypeScript strict, Vite + React (UI), Three.js (3D), Electron
(настольная сборка).

| Пакет | Что внутри |
|---|---|
| `packages/engine` | движок: тик, вывод на линию, драйверы, расписание, Modbus, RDM, Telegram, WebSocket-сервер для редактора |
| `packages/shared` | общие типы и чистые функции (проект, сцены, аудиоанализ, геометрия) — используются и движком, и UI |
| `packages/ui` | редактор (React) |
| `packages/app` | обёртка Electron: собирает движок в один `engine.cjs` и поднимает его как дочерний процесс |

Движок и редактор — **разные процессы**, связь по WebSocket (порт 9520). Шоу
играет движок: если закрыть редактор, фонтан продолжает работать. Это
принципиально, ломать нельзя.

## Как запускать

```bash
npm install
npm run dev          # движок (9520) + UI (5180) — основной режим разработки
npm run app:dev      # то же + окно Electron
npm run app:dist     # установщик под Windows
```

## Обязательные проверки перед сдачей

Гонять всё, а не выборочно. Ни один пункт не «и так понятно».

```bash
npm run typecheck                                   # все пакеты
npm run build                                       # сборка UI
npm run smoke                                       # сквозной тест движка
npm -w @fountain-studio/engine run projects-test      # объекты: папки, недавние, переезд
npm -w @fountain-studio/engine run dirty-guard-test  # диалог о несохранённых правках при переключении
npm -w @fountain-studio/engine run license-test      # подпись/срок лицензии, отзыв по сети
npm -w @fountain-studio/engine run appbackup-test    # копия настроек программы: выгрузка и возврат
npm -w @fountain-studio/engine run schedule-test     # расписание при прыжках часов (сон ПК, перевод времени)
npm -w @fountain-studio/engine run editors-test      # два редактора сразу: чужая правка не затирается
npm -w @fountain-studio/engine run musidora-test     # кадр USB-DMX FountanPlay
npm -w @fountain-studio/engine run failsafe-test     # аварийное отключение
npm -w @fountain-studio/engine run eventlog-test     # журнал на диске
npm -w @fountain-studio/engine run wind-test         # ветер: порог, выдержки, борт чаши, датчик Modbus/MQTT
npm -w @fountain-studio/engine run worker-test       # расчёт в отдельном потоке
npm -w @fountain-studio/engine run telegram-test     # уведомления
npm -w @fountain-studio/engine run audio-test         # звук: громкость, вырезки монтажа
npm -w @fountain-studio/engine run lines-test         # вселенные и такт на ходу, без провала значений
npm run app-test                                     # УСТАНОВЛЕННАЯ программа: движок из сборки, окно, значок у часов, автозапуск
```

Визуальные правки (3D, вёрстка) проверяются **своими скриншотами**, а не «по
описанию»: поднять Electron-окно на `http://127.0.0.1:5180`, снять кадр,
посмотреть глазами. Делали по образцу — сверять 1 в 1 с образцом.

Как снимать (редактор поднят через `npm run dev`):

```bash
# только смотреть рабочий движок (9520) — ничего не нажимать, кроме вкладок:
env -u ELECTRON_RUN_AS_NODE npx electron scripts/ui-shot.cjs сценарий.json
# нажимать что угодно — на изолированном движке (9531, своя папка, демо-проект):
npm -w @fountain-studio/engine run ui-shots -- сценарий.json
```

Формат сценария — в шапке `scripts/ui-shot.cjs`: вкладки и кнопки по тексту,
прокрутка, снимок (целиком или фрагмент крупно), `fit` — поиск обрезанных,
срезанных по высоте и уехавших за край окна подписей. VS Code выставляет
`ELECTRON_RUN_AS_NODE`, и без `env -u` Electron стартует как голый Node.
Проверять шапку на ширинах 1280, 1366, 1600 и 1920. Снимок не заменяет
проверку DOM: после нажатия сверять состояние через `eval`, иначе можно
«нажать» не туда и не заметить.

## Правила, которых держимся

1. **Комментарии и весь текст интерфейса — по-русски.** Комментарий объясняет
   ПОЧЕМУ так сделано (и от какой грабли это спасает), а не пересказывает код.
2. **Доводить каждый пункт до конца.** «Не успел», «сделал частично» не
   принимается: если в запросе пять пунктов — делаются все пять.
3. **Подписи должны влезать.** Текст в списках, кнопках и таблицах не обрезать;
   не влезает — сокращать или переименовывать, и проверять самому до сдачи.
4. **Не трогать рабочие данные пользователя.** Тесты и проверки не пишут в
   `fountain.project.json` и `fountain.config.json` рабочей папки: поднимать
   отдельный движок на своём конфиге (порт 9531) или изолированную сцену.
5. **Честный отчёт.** Не заработало — так и писать, с выводом. Не проверено на
   железе — писать «не проверено», а не «работает».
6. **Секреты в репозиторий не кладём.** Токен Telegram и прочие пароли живут в
   `fountain.secrets.json` рядом с проектом (в `.gitignore`), наружу уходит
   только «настроено / не настроено».
7. **Каждый законченный запрос: запись в журнал → коммит → пуш.** Подробности
   ниже.

## Документы проекта

| Файл | Зачем |
|---|---|
| `docs/ЖУРНАЛ.md` | **что сделано в каждой сессии и что осталось** — читать первым, чтобы понять, на чём остановились |
| `docs/IDEAS.md` | список задач: что делаем дальше (в порядке), что уже сделано |
| `docs/ARCHITECTURE.md` | архитектурные решения и итоги фаз, по датам |
| `docs/USB-DMX.md` | железо вывода: ENTTEC PRO / Open DMX / интерфейс FontanPlay, формат кадра |
| `docs/USB-DMX-проверка-на-объекте.md` | памятка человеку на объекте (пересылается тестировщику) |
| `docs/FONTANPLAY-REFERENCE.md` | конспект старой программы FontanPlay — что она умела |
| `docs/MANUAL.md` | руководство пользователя (встроено в приложение) |
| `docs/УСТАНОВКА.md` | установка на новый компьютер: Windows, лицензия, драйверы FTDI и RS-485, ffmpeg, сеть, автозапуск |
| `docs/ТЕРМИНЫ.md` | как называть вещи в интерфейсе: правила именования и принятые термины |

Технические разборы держим в тематических файлах, а `IDEAS.md` — только список
задач, иначе он превращается в свалку.

## Порядок сдачи работы

**Один законченный запрос — один коммит.** Не копить работу, чтобы потом
свалить всё в один огромный коммит: по такой истории невозможно понять, что
когда менялось, и нельзя откатить одну неудачную правку, не задев остальное.
Если в запросе несколько независимых кусков (драйвер, безопасность, документы) —
делать несколько коммитов, по куску на коммит.

В конце каждого законченного запроса, **без отдельного разрешения**:

1. Прогнать проверки из раздела выше.
2. Дописать запись в `docs/ЖУРНАЛ.md`: дата, что сделано, что не доделано,
   что проверено и чем.
3. Отметить в `docs/IDEAS.md` сделанное (✅/◐) и поправить порядок задач.
4. `git add` изменённого, коммит осмысленным сообщением по-русски.
5. `git push` в `origin main`.

Работают двое с разных машин, поэтому: **перед началом работы `git pull`**, в
конце — пуш. Незапушенная работа не видна второму разработчику, а разошедшиеся
рабочие деревья — главный риск при двоих.

## Чего нельзя делать

- Останавливать вывод на линию при закрытии редактора (шоу играет движок).
- Публиковать секреты, лицензии и приватные ключи.
- Коммитить рабочие данные объекта: `fountain.project.json`, `audio/`,
  `backups/`, `logs/`, `fountain.license.json`.
